# 日用铺电商系统设计

国内生活日用品店。清洁、厨房、收纳、个护、小百货。一家店先卖自己的货，数据按店铺隔开。本文是功能与数据设计，开发按文末顺序做。

当前代码里只有门户用户表。登录只核对账号是否存在，不核对密码。库里只留 koko，昵称是超级管理员。AI 对话和 WebSocket 已删除。

## 1. 账号怎么分

系统里只有两种东西会长期存在：用户和店铺。

用户是能登录的人。店铺是租户，也是卖货的那一家店。商品、库存、购物车、订单、优惠券都带店铺编号，一家店看不见另一家店的数据。

商户不是第三套登录账号。店名、联系人、手机、地址、营业时间、公告、收款说明，都是这家店的资料。

同一个人可以既买东西又管店。买东西不需要再注册一个账号。管哪一家店，由「店铺成员」决定，不写死在用户表的一个角色字段上。

| 身份 | 存在方式 | 能做什么 |
| --- | --- | --- |
| 平台超级管理员 | 用户上的平台身份，目前只有 koko | 建店、停店、看所有店的经营数据。不代替店员改价、改库存、发货 |
| 店主 | 某家店的成员 | 改本店资料、商品、订单、店员、优惠券、售后 |
| 店员 | 某家店的成员 | 改库存、上下架、发货、处理本店售后。不能改店资料、不能增删店员、不能改角色 |
| 顾客 | 任何正常用户默认都是 | 浏览在售商品、加购、下单、付自己的款、看自己的订单和售后 |

koko 不挂在「日用铺」的店员名单里。她要看经营情况时，从平台入口进某家店的只读概览。

第一家店就叫「日用铺」。表上从第一天就有店铺编号，以后开第二家店不用改表。

## 2. 页面风格

已经定下来，后面的店面和后台都用这一套。

- 底色纯白，分割线 `#E5E5E5`，后台侧栏纯黑 `#111111`。
- 按钮纯黑，当前菜单纯蓝 `#2563EB`。
- 标题用宋体，正文用苹方或微软雅黑。
- 按钮胶囊形，卡片圆角，留白多。
- 店面没有黑色侧栏。顶部是店名、搜索、购物车、账号。内容区白底、大图、少按钮。

## 3. 登录与账号

### 3.1 注册

店面提供注册。账号用手机号，密码 6 到 64 位，密码只存 BCrypt。注册成功即登录，身份是顾客，不自动成为任何店的店员。

后台不开放自行注册。店主和店员由 koko 或该店店主创建，创建时指定手机号、初始密码和店铺角色。

### 3.2 登录

一个登录入口。登录后按身份进不同的地方：

- 只有顾客身份：进店面。
- 是某家店的店主或店员：进该店后台。若同时是多家店的成员，先选店。
- koko：进平台后台。平台后台可以打开某一家店的只读概览，不能在里面改货。

停用账号不能登录。密码错误、账号不存在，提示同一句「账号或密码不正确」，不透露账号是否存在。

连续失败 5 次，锁定 15 分钟。退出登录使当前令牌失效。

### 3.3 个人资料

可改昵称、头像、邮箱。手机号单独验证后再改。可改密码，必须填当前密码。

顾客可以维护收货地址。地址属于用户本人，不属于某一家店。下单时把当时的地址抄进订单，之后改地址不影响已下的单。

地址字段：收件人、手机、省、市、区、详细地址、是否默认。每人最多 20 条。默认地址只有一条，新的默认会取消原来的默认。

## 4. 店铺

### 4.1 平台能做的

- 新建店铺：店名、店主（必须是已有用户）、联系人、手机、发货地址。
- 停用店铺：店面立即不可访问，不能下新单。未完成订单仍可发货和售后。
- 启用店铺。
- 查看每家店的在售商品数、待发货数、今日支付金额。只读。

### 4.2 店主能改的资料

店名、简介、公告、联系人、联系电话、发货地址、营业说明、店招图。店招图一张，简介 500 字以内。

店主可以添加、停用本店店员，可以把店员升为店主。一家店至少保留一名店主，不能把最后一名店主移除。

店员名单只显示本店。koko 不出现在店员名单里。

## 5. 类目与商品

### 5.1 类目

每家店自己的类目，两级。一级是货架，二级是细分。

日用铺开店时写入这五组，店主以后可以改名、停用、增加：

- 家居清洁：纸巾、清洁剂、垃圾袋
- 厨房：餐具、保鲜盒、厨具小件
- 收纳：收纳盒、挂钩、袋
- 个护：洗护、口腔、棉品
- 小百货：文具小件、家用杂件、一次性用品

停用的类目不在店面出现。类目下仍有上架商品时不能删除，只能停用。

### 5.2 商品

一件商品是一个 SPU。规格是 SKU。没有多种规格的商品，也建一条默认 SKU，价格和库存都在 SKU 上。

商品字段：

- 名称，2 到 60 字
- 卖点，200 字以内，可空
- 类目，必须选到二级
- 主图至少 1 张，最多 8 张，第一张是封面
- 详情图文，可空
- 上架状态：草稿、在售、已下架
- 排序，数字越小越靠前

SKU 字段：

- 规格名，例如「白色 / 大号」。默认规格名写「默认」
- 售价，单位分，必须大于 0
- 划线价，可空，只展示，不参与结算
- 库存，整数，不能为负
- 货号，店内唯一，可空
- 重量，克，可空，留给以后算运费
- 启用或停用。停用的规格不能加购

上架要求：至少一张主图，至少一个启用且库存大于 0 的 SKU。不满足时保存为草稿，不能直接在售。

下架后店面不可见，已加入购物车的条目在结算时提示「已下架」并拦下。

删除用停用，不物理删除有过订单的商品和 SKU，避免历史订单对不上。

### 5.3 库存

库存只在 SKU 上。每次变化写一条库存流水：变动数量、变动后库存、原因、关联订单号、操作人、时间。

原因只有这些：初始入库、手动调整、下单锁定、支付扣减、取消释放、售后退回。

下单时锁定库存，不立刻扣成销量。锁定 30 分钟。超时未支付的订单自动取消，并释放锁定。支付成功后把锁定转成扣减。库存不足时整单不能提交，不接受部分规格先占着。

店员改库存时填调整后的数量和原因。调整不能把「可售库存」打成负数。可售库存 = 现库存 − 未支付订单锁定量。

## 6. 店面

顾客看到的页面，不使用后台侧栏。

### 6.1 首页

- 店名和一句简介
- 公告一条，没有公告就不显示
- 搜索框
- 五个一级类目入口
- 在售商品，按排序和上新时间，先显示 12 个，可以继续加载

### 6.2 列表

路径带类目。显示该类目下在售、且至少一个 SKU 可售的商品。

可按价格从低到高、从高到低、最新上架排序。每页 12 个。没有货时显示「这个分类还没有商品」。

### 6.3 搜索

搜本店在售商品的名称和卖点。两字起搜。结果页与列表同一套卡片。没有结果时提示换个词，不推荐别的店。

### 6.4 详情

封面大图，可切换其余主图。名称、卖点、价格、库存、规格选择、数量、加入购物车、立即购买。

详情图文在下方。已下架或库存为 0 的规格不能选。全部规格都不可买时，按钮为「暂时缺货」，不能提交。

数量默认 1，最大不超过该规格可售库存，单次不超过 99。

### 6.5 购物车

按店铺分组。现在只有日用铺一组，结构按多店留着。

每行：图、名称、规格、单价、数量、小计、删除。数量变化时重新校验库存。失效行（下架、规格停用、库存变成 0）单独放在下面，不能勾选，可以删除。

勾选后显示合计件数和金额。去结算只带勾选的、仍然可售的行。未登录可以在本机暂存购物车，登录后与账号购物车合并：同一 SKU 数量相加，超过库存时收成库存数。

### 6.6 确认订单

展示商品、数量、单价、运费、优惠、应付。运费第一期固定为 0，页面写「包邮」。

必须选一个收货地址。没有地址时先去新增。

买家留言 200 字以内，可空。

提交时再次校验：商品仍在售、库存足够、价格与当前 SKU 价格一致、优惠券仍可用。价格变了就停在确认页，显示新价格，让顾客再点一次提交。

提交成功生成待付款订单，并锁定库存，跳到支付页。

## 7. 订单

### 7.1 金额

所有金额用分，整数。展示时再换成元，保留两位。

订单金额：

- 商品总额 = 各行单价 × 数量
- 运费
- 优惠额
- 应付 = 商品总额 + 运费 − 优惠额，最小为 0

单价以提交订单时的 SKU 价格为准，写入订单行，之后改价不影响这笔单。

### 7.2 状态

| 状态 | 含义 | 顾客能做 | 店里能做 |
| --- | --- | --- | --- |
| 待付款 | 已下单，库存已锁定 | 去支付、取消 | 不能发货 |
| 待发货 | 已支付 | 申请退款 | 填快递公司和运单号，发货 |
| 待收货 | 已填运单 | 确认收货、申请售后 | 改运单号一次 |
| 已完成 | 顾客确认，或发货满 7 天自动确认 | 评价、申请售后（7 天内） | 看评价 |
| 已取消 | 顾客取消，或 30 分钟未支付 | 再买一单 | 无 |
| 退款中 | 售后处理中 | 看进度、补充说明 | 同意或拒绝 |
| 已退款 | 钱已退回，或未发货退款完成 | 看记录 | 看记录 |

已取消、已退款是结束状态。一笔订单同一时刻只有一个主状态。部分退款先不做，售后按整单。

自动任务：

- 每分钟扫描待付款超过 30 分钟的订单，取消并释放库存。
- 每天扫描待收货满 7 天的订单，改成已完成。

### 7.3 顾客的订单页

列表按状态筛选：全部、待付款、待发货、待收货、已完成、退款。每行显示订单号、时间、商品封面和名称、件数、应付、状态。

详情显示收件信息、留言、商品行、金额明细、支付时间、快递公司和运单号、状态记录。运单号可复制。第一期不对接快递轨迹，只展示单号。

取消待付款订单要确认。取消原因可选：不想要了、信息填错、重新下单。

### 7.4 后台订单

店主和店员看本店订单。可按状态、订单号、收件人手机、下单日期筛选。

待发货详情里填快递公司（从常用列表选：顺丰、中通、圆通、韵达、申通、京东、邮政、其他）和运单号。运单号 6 到 40 位。保存后状态变为待收货，并记下发货人和发货时间。

待发货订单如果顾客已申请退款，发货按钮不可用，先处理售后。

## 8. 支付

国内只接微信支付和支付宝，二选一或都接。没有商户号之前，支付页可以标明「支付未开通」，订单停在待付款，不提供「我已付款」这种假按钮，避免账对不上。

支付流程：

1. 顾客在待付款订单选择支付方式。
2. 服务端向微信或支付宝下预付单，金额必须等于订单应付，不能由前端传入金额。
3. 顾客完成支付。
4. 以支付平台的异步通知为准，把订单改为待发货，写支付单号、支付时间、实付金额，并把库存锁定转为扣减。
5. 页面上的「支付成功」只做展示。若通知还没到，订单仍显示待付款，并提示稍候刷新。

同一订单重复通知只入账一次。金额不一致、订单已取消、订单已支付，都拒绝入账并记录原因。

退款原路退回。退款单号、退款金额、退款时间单独落表。

## 9. 售后

未发货：顾客在待发货状态申请「仅退款」，原因有不想要了、拍错、地址错误、其他。店主或店员同意后，订单进入退款中，支付原路退回，库存退回，完成后是已退款。拒绝时必须填写理由，订单回到待发货。

已发货或已完成 7 天内：顾客申请「退货退款」。要填原因和说明，说明 300 字以内。店里同意后给出退货收件信息（默认用店铺发货地址）。顾客填写退货运单号后，店里确认收货，再发起退款。拒绝时订单回到原状态。

超过确认收货 7 天不能再申请。退款中的订单不能再发货、不能再评价。

售后列表在后台单独一页，按待处理、已同意、已拒绝、已完成筛选。

## 10. 评价

仅已完成且未评价的订单可以评价。一笔订单评一次，不按商品拆开。

字段：1 到 5 星、文字 10 到 300 字、图片最多 3 张。提交后不能改、不能删。店面详情页展示该商品相关订单的评价，每页 10 条，默认最新。没有评价就不显示评价区。

店主不能删除差评。后台只能看。

## 11. 优惠券

店主创建本店优惠券。

字段：名称、门槛金额、减免金额、发放数量、每人限领、开始时间、结束时间、状态。

规则：

- 减免金额必须小于门槛。
- 顾客在领券中心领取，或店主把券发给指定用户。
- 下单时可选一张，不可叠加。
- 商品总额达到门槛才能用。运费不参与门槛。
- 券在提交订单时占用，支付成功后核销，取消或超时未支付则退回。
- 过期券不能领、不能用。

第一期可以先不做领券中心页面，但表和结算规则按上面设计，避免以后改订单金额结构。

满减、拼团、秒杀、直播带货不在本系统里做。

## 12. 后台页面

平台后台，只有 koko：

- 工作台：店铺数、全部待发货数、今日支付金额
- 店铺列表：新建、停用、进入某店只读概览
- 用户：查询、停用、重置密码。不能在这里把人设成某店店主，设店主在店铺成员里做

店铺后台，店主和店员：

- 工作台：今日订单数、今日支付金额、待发货、待处理售后、在售商品数
- 商品：列表、新建、编辑、上下架
- 类目：两级维护
- 库存：按 SKU 看可售数量，手动调整，看流水
- 订单：筛选、详情、发货
- 售后：处理退款和退货
- 评价：只读列表
- 优惠券：店主可建券；店员只读
- 店铺资料和成员：仅店主

顾客端：

- 首页、类目列表、搜索、详情
- 购物车、确认订单、支付结果
- 我的订单、订单详情、申请售后
- 地址管理、优惠券、个人资料

## 13. 表

金额全部是分，BIGINT。主键雪花 BIGINT。时间 DATETIME。删除用 `del_flag`，有订单引用的商品和 SKU 不物理删除。

### shop 店铺

| 字段 | 说明 |
| --- | --- |
| id | 主键，也是全系统的租户编号 |
| name | 店名 |
| intro | 简介 |
| notice | 公告，可空 |
| contact_name | 联系人 |
| contact_mobile | 联系电话 |
| ship_address | 发货地址，售后退货也默认用它 |
| banner_url | 店招，可空 |
| status | 0 营业，1 停用 |
| del_flag / version / create_time / update_time | 与现有用户表一致 |

### shop_member 店铺成员

| 字段 | 说明 |
| --- | --- |
| id | 主键 |
| shop_id | 店铺 |
| user_id | 用户 |
| role | OWNER 店主，STAFF 店员 |
| status | 0 正常，1 停用 |

同一用户在同一店铺只能有一条记录。

### sys_user 在现有字段上增加

| 字段 | 说明 |
| --- | --- |
| password_hash | BCrypt |
| platform_admin | 0 否，1 是。koko 为 1 |
| avatar_url | 可空 |

部门字段不再用于电商权限，可以留着不动。

### user_address 收货地址

user_id、receiver、mobile、province、city、district、detail、is_default。

### category 类目

shop_id、parent_id（一级为 0）、name、sort、status。

### product 商品

shop_id、category_id、name、selling_point、detail、status（草稿、在售、下架）、sort。

### product_image

product_id、url、sort。sort 为 0 的是封面。

### product_sku

product_id、shop_id、spec_name、price、list_price、stock、locked_stock、sku_code、weight_gram、status。

### stock_log 库存流水

shop_id、sku_id、change_qty、after_stock、reason、order_id、operator_id、create_time。

### cart_item 购物车

user_id、shop_id、sku_id、quantity。同一用户同一 SKU 一条。

### order_info 订单

| 字段 | 说明 |
| --- | --- |
| id | 主键 |
| order_no | 展示用订单号，店内唯一 |
| shop_id / user_id | 店铺和顾客 |
| status | 第 7 节的状态 |
| goods_amount / freight_amount / discount_amount / pay_amount | 分 |
| receiver_name / receiver_mobile / receiver_address | 下单时抄下来的地址 |
| buyer_remark | 留言 |
| pay_channel | WECHAT 或 ALIPAY，未支付为空 |
| pay_no | 支付平台单号 |
| pay_time | 支付时间 |
| ship_company / ship_no / ship_time / ship_user_id | 发货 |
| finish_time / cancel_time / cancel_reason | 结束信息 |

### order_item 订单商品

order_id、sku_id、product_name、spec_name、image_url、price、quantity、amount。名称、规格、图片、单价都是下单快照。

### order_log 订单状态记录

order_id、from_status、to_status、operator_id、remark、create_time。每次状态变化写一条。

### payment 支付记录

order_id、channel、amount、out_trade_no、platform_trade_no、status（待支付、成功、失败）、notify_body、create_time。

### refund 售后

order_id、shop_id、user_id、type（仅退款、退货退款）、reason、description、status（待处理、已同意、待退货、已收货、已拒绝、退款成功）、refund_amount、refuse_reason、return_ship_no、create_time、finish_time。

### review 评价

order_id、shop_id、user_id、product_id、score、content、image_urls、create_time。一笔订单一条。

### coupon 优惠券

shop_id、name、threshold_amount、reduce_amount、total、received、per_user_limit、start_time、end_time、status。

### coupon_user 领用

coupon_id、user_id、status（未使用、已占用、已使用、已退回、已过期）、order_id。

## 14. 权限核对

每个店铺接口都从登录态取用户，再查 `shop_member`。平台接口只允许 `platform_admin = 1`。

顾客接口只返回自己的购物车、订单、地址、券。用别人的订单号访问，返回不存在。

店员调用改店资料、改成员、建优惠券，返回无权限。koko 调用改库存、发货，返回无权限。

列表查询必须带店铺条件。平台概览可以不带，但只能出汇总数字和店铺名单，不出顾客手机号全文。手机号在列表里中间四位打星，详情里店主和店员能看完整号码，因为要发货。

## 15. 接口分组

前缀沿用 `/api`。下面是能力，不是最终路径全文。

- 认证：注册、登录、退出、改密码、改资料
- 店铺：平台建店停店、店主改资料、成员列表与变更
- 类目：列表、保存、停用
- 商品：分页、详情、保存、上下架
- SKU 与库存：保存规格、调整库存、流水
- 店面：首页、类目商品、搜索、详情、评价列表
- 购物车：列表、改数量、删除
- 地址：列表、保存、删除、设默认
- 订单：确认页计价、提交、顾客列表、详情、取消、确认收货
- 发货：后台发货
- 支付：发起支付、支付通知
- 售后：申请、后台处理、顾客退货运单
- 优惠券：建券、领取、下单可用列表

写接口都要校验店铺和角色。金额由服务端计算。

## 16. 建设顺序

1. 密码登录、店铺、店铺成员。koko 仍是平台管理员。建出「日用铺」，并指定一名店主。
2. 类目、商品、SKU、图片、库存流水。后台能上架。
3. 店面首页、列表、详情、搜索。
4. 地址、购物车、下单、锁定库存、超时取消。
5. 后台订单和发货，顾客确认收货。
6. 接微信支付或支付宝，以及未发货退款。
7. 退货退款、评价。
8. 优惠券接到结算。

每一步都能单独使用。支付没接上之前，订单可以停在待付款，不能用手工把状态改成已支付。

## 17. 明确不做

- 不把商户做成另一套账号，也不做商家入驻审核、抽成、分账。
- 不做跨店合并支付。一家店一笔订单。
- 不做多规格以外的批发价、会员价、积分。
- 不做拼团、秒杀、直播、分销。
- 不做快递轨迹查询，只记录公司名和运单号。
- 不做 AI 对话、WebSocket、消息广播。
